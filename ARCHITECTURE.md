# PDFin Workspace Architecture

## Repository ownership boundary

This repository is the source of truth for the full PDFin application.

```
pdfin-workspace
├── backend        # Axum services and processing logic
├── shared         # API contract, DTOs, shared domain types
└── frontend-react # React UI and frontend integration
```

## Frontend boundary

Frontend contributors should work inside:

```
frontend-react/
```

Frontend must consume backend capabilities through API contracts. Do not duplicate backend business rules in the frontend.

## Backend boundary

Backend owns:

- PDF processing
- file lifecycle
- validation enforcement
- conversion execution
- API implementation

## Shared boundary

Shared is the contract layer between frontend and backend.

It should contain:

- request DTOs
- response DTOs
- operation enums
- API error schemas

It should not contain application-specific processing logic.

## Integration rule

Changes that modify API shape must update shared contracts first, then backend and frontend clients.

## API versioning

The public API lives under `/api/v1` (built in `backend/src/routes/v1`):

- `GET /api/v1/health` — liveness.
- `POST /api/v1/pdf/*` — merge, split, pages, rotate, compress, watermark, page-numbers (sync multipart → binary result).
- `POST /api/v1/convert/*` — pdf-to-word, pdf-to-excel, pdf-to-jpg, word-to-pdf, excel-to-pdf, jpg-to-pdf.
- `GET /api/v1/openapi.yaml` — served from `docs/openapi.yaml`; keep the two in sync.

The legacy `/rust-api/*` routes are kept as compatibility aliases and are deprecated — new work must use `/api/v1`.

### Error contract

Every response carries an `x-request-id` header (echoed from the client or generated by `backend/src/middleware/request_id.rs`). JSON error responses use the envelope

```json
{"error": {"code": "…", "message": "…", "request_id": "…"}}
```

with `request_id` present whenever the middleware ran. The schema lives in `shared::ApiError` and is documented in `docs/openapi.yaml`.

### Adding a new endpoint

1. Implement/extend the handler (existing handlers live in `backend/src/handlers` and `backend/src/features/convert`).
2. Mount it in `backend/src/routes/v1/<group>.rs` under `/api/v1`.
3. Document it in `docs/openapi.yaml` (served at `/api/v1/openapi.yaml`).
4. Update the frontend client (`frontend-react/src/lib/api/*`).
